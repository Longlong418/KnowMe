# Kimi K3,讲给有统计脑的你看

*(原文配套的那张白板图已从仓库移除,只剩生成脚本 `knowme/ops/whiteboard/build_k3_tutorial.py`。)*

写给**统计功底很好、但有一阵子没碰深度学习**的人。每个概念都锚定在一件你已经在用的东西上 ——
加权平均、在线估计、混合模型、boosting、memoization —— 于是术语就不再是术语了。

**一句话的心智模型。** Attention 是对词做的加权平均;KDA 把它变成***滚动***平均
(线性代价,不是 n 平方);AttnRes 让层能复用更早的层,像 boosting 的各个阶段往回伸手;
MoE 是一个稀疏混合模型,每次输入只评估少数几个成分;serving 纯粹是运维 ——
把「读」和「写」拆开,并把上下文 memoize 掉,于是重复的循环变便宜;而那个价签,不过是这些节省被传导下来的结果。

## 白板,一节一节讲

### 1. MoE —— 一个 2.8T 的大脑,同时醒着的只有约 50B

**基本想法。** MoE(Mixture of Experts,专家混合)不是一个大网络,而是持有许多小的「专家」子网络
(896 个),外加一个**路由器**,它为每个词挑出最相关的少数几个专家(16 个)。**只有那几个会起火。**

**统计类比。** 这就是一个**带门控函数的混合模型** —— 90 年代初 Jacobs & Jordan 那套
mixture-of-experts 的老想法:一个 gate 把每个输入分配给各个成分,每个成分是它自己的小回归。
新意在于***稀疏性*** —— 你只评估 **top-k 个成分**,而不是全部。
就像一个混合模型,其中你把所有 responsibility 可忽略的成分全部跳过。

**K3 做了什么。** 总共***拥有*** 2.8T 参数,但每个 token 只有约 50B ***活跃***(896 选 16)。
「Stable LatentMoE」= 路由在一个压缩的(隐)空间里完成,并且被调得不抖。
「Quantile Balancing」= 保持各成分使用率均衡,于是没有专家过劳、也没有专家饿死
(避免混合模型退化的那种失败模式)。

> 这么说: *「拥有一座宅子,但每位客人只开一个房间的灯 —— 前沿模型的体量,中型模型的运行成本。」*

### 2. Attention → KDA(Kimi Delta Attention)

**基本想法。** 对每个词,attention 问「其他每个词对我有多相关?」,把这些相关度变成权重,
然后对它们的 value 做加权求和。

**统计类比。** 那就是一个**核加权估计量**(Nadaraya–Watson):权重是一个相似度核,
输出是一个加权平均。为了得到权重,它要比较**每一对**词 —— 一个 n×n 的矩阵,
就像完整的 Gram / 成对距离矩阵。n 个词 → n 平方的工作量。**词数翻倍 → 工作量 4 倍。**
到 100 万词,这就致命了。(这个「n 平方」就是长上下文昂贵的全部原因。)

**K3 做了什么。** KDA ***递归地***算同一件事,而不是重算。你永远不会靠「每来一个新点就把所有数据重新求和」来得到均值 ——
你会维护一个**滚动均值并更新它**(Welford),或者一个**指数加权移动平均**,或者一个
**递归最小二乘 / Kalman** 更新。KDA 携带一个小的**状态矩阵(充分统计量)**,一个 token 一个 token 地更新它 ——
线性代价,不是二次的。那个 **「Delta」** 就是 delta rule:用修正量来更新 ——
擦掉过时的关联,写入新的 —— 就像 (x, y) 数据点流进来时在线更新回归系数。

那些粉色的 **「full attention checkpoint」** 行:递归估计量会随着近似误差的累积而**漂移**,
所以每隔几层 K3 会做一次***精确的***完整 attention 来重新锚定 ——
就像定期在全量数据上重新拟合一次,以修正漂移。

> 这么说: *「KDA 就是「用滚动平均的方式算出来的 attention」,而不是每一步把所有东西重新求和。」*

### AttnRes(Attention Residuals)

**基本想法。** 深层网络把层叠起来。**残差连接**让每层输出 `input + f(input)` ——
它维护一个滚动总和,每层加上一个***修正量***。

**统计类比。** 那就是 **梯度 boosting**:每个阶段拟合剩下的部分(残差),然后把各阶段的贡献加起来。
这正是让你能叠 100 层而不让信号退化的原因。标准残差是**一阶**的 ——
第 *k* 层只建立在第 *k-1* 层上(类马尔可夫:每个状态只依赖前一个)。

**K3 做了什么。** AttnRes 让靠后的层可以取***所有***更早层的**学习出来的加权组合**,
而不只是紧邻的那一层 —— 它***在深度上做 attention***。把它想成对**所有先前的 boosting 阶段**做一次回归,
而不只是对最近那一个 —— 一个学习出来的混合,哪个更早的特征阶段有用就复用哪个。

> 这么说: *「AttnRes = 每一层都能复用任何一个更早层的成果,而不只是紧挨着它的那一层。」*

### 3. Serving —— 为循环而造

这跟建模完全无关 —— 这是**跑已训练模型**的**运维**。

**两个阶段,profile 完全相反。**
- **Prefill** = 一次性读入你的整个 prompt(所有输入 token 并行)→ **计算密集**,吞吐型任务。
- **Decode** = 一个 token 一个 token 地写出答案 → **串行**,延迟受限。

这两者差别之大,就像夜间批处理任务和实时网页请求。**分离式推理(disaggregated inference)** =
把它们跑在***分开的机器池***上,各自为自己那类活调优(和把重 ETL 与低延迟查询服务分开是同一个直觉)。

**Cache = 对充分统计量的 memoization。** 生成过程中,模型把它已经处理过的 token 的表示(keys/values)存下来 ——
一个 **KV cache** —— 于是不必重算。就是纯粹的 **memoization**:别对已经看过的数据重算统计量。

**为什么这对智能体重要。** 一个智能体循环每一轮都重发**几乎相同**的上下文。其中绝大部分已经在缓存里 →
一次**缓存命中** → 你只付约 1/10 的钱(每百万 token $0.30 对 $3)。**K3 就是被工程化成「重复的智能体循环很便宜」。**

> 这么说: *「把读和写拆到不同机器上,而且永远不要重算你已经见过的上下文。」*

### 4. 那个价签($/M tokens)

**基本想法。** 定价按**每百万 token** 报价(一个 token 大约是一个词的 3/4),拆成***输入***(你发过去的)
和***输出***(它生成的)。这里 K3 两边都比 Opus 4.8 / GPT 5.5 便宜,而且即使到 1M 上下文,价格**依然持平**。

**统计类比。** 把它想成**每个观测的边际成本**。三个更早的设计选择各自把这个边际成本压下去,
而那个价签只是这些节省被传导下来:
- **MoE** → 每个 token 只有约 2% 的参数在计算(每 token 的***算力***便宜)。
- **KDA** → attention 是线性的,所以多一个 token 的边际成本不随上下文增长而爆炸
  (***这就是为什么 1M 上价格平坦*** —— 没有 n 平方的惩罚)。
- **Cache** → 重发的上下文是一次缓存命中,于是智能体循环里***实际***输入价格塌到 $0.30。

所以卡片上那些数字不是随便填的 —— **它们是「稀疏 + 线性 attention + memoization」在财务上的直接投影。**

> 这么说: *「便宜且平坦,因为每一个额外 token 的边际成本被三种不同的方式工程化地压低了。」*

## 语言模型简史

整个领域就是一个问题、每个时代答得更好一点:**给定到目前为止的词,预测下一个词。**

### 词袋(Bag-of-words)
**想法。** 统计出现了哪些词;忽略顺序。**统计类比。** 一个多项分布 / 词频向量 ——
一个 token 的直方图。「不好」和「好不」完全一样,因为直方图没有顺序。
> 这么说: *「拿到了主题,丢掉了含义。」*

### LSTM
**想法。** 从左到右读,边读边携带一份记忆。**统计类比。** 序列上的一个
**状态空间模型 / 递归滤波器** —— 每一步更新一个隐状态(有 Kalman 的味道)。
两个缺陷:串行(慢),而且状态在长间隔上会衰减(忘掉开头)。
> 这么说: *「一个只有短期记忆的读者 —— 这些你当年自己建过 —— 但慢,而且健忘。」*

### Attention(2017)—— 转折点
**想法。** 不再维护一个滚动状态,而是**一次性看所有词**,并对重要的加权。
**统计类比。** 就是第 2 节里那个核加权平均 —— 但**并行**地在整个序列上计算,
于是既没有串行瓶颈,也不会忘掉开头。
> 这么说: *「那次突破 —— 整场演讲就靠这一个想法撑着。」*

### Transformer
**想法。** 把 attention 叠成很多层。**统计类比。** 把加权平均这个操作和残差(boosting)连接**复合**起来,加深。
**这是架构本身,不只是个技巧。**
> 这么说: *「Attention 是发动机;Transformer 是整辆车。」*

### LLM
**想法。** 拿一个 Transformer,做得极大,在整个互联网上训练它预测下一个词。
**统计类比。** 在一个荒谬的规模上做「下一个 token 分布」的最大似然拟合 ——
而通用能力(写作、编程、推理)从这**单一目标**里**涌现**出来。
> 这么说: *「这就是 ChatGPT / Claude / Kimi —— 你实际在用的那个东西。」*

### 成本墙
**想法。** 规模不是免费的。**统计类比。** 两笔成本:要便宜地跑起来,参数太多;以及 attention 的 **n 平方** ——
词数翻倍,工作量四倍(第 2 节)。**这是长上下文身上那张隐藏的价签。**
> 这么说: *「这就是为什么「更大、记忆更长」的模型本应贵到用不起。」*

### Kimi K3
**想法。** Transformer/LLM 的思路,用三个技巧***击败***了这堵墙。**回顾。**
MoE(稀疏混合 → 算力便宜)、KDA(滚动平均式 attention → 干掉 n 平方)、
FP4(低精度数值 → 小 4 倍)。**每一个攻击墙的一部分。**
> 这么说: *「前沿规模、百万词记忆,但定价便宜到能跑起来 —— 这才是新的地方。」*

## 术语表 —— 每个缩写配一个统计孪生

| 术语 | 大白话 | 统计孪生 |
|---|---|---|
| **MoE** | 很多小专家,每个词只有少数几个点火 | 稀疏混合模型 + 门控(top-k 成分) |
| **活跃参数 vs 总参数** | 拥有的 vs 每个 token 实际在算的 | 完整模型 vs 你实际评估的那些成分 |
| **Attention** | 对所有词做加权回望 | 核加权平均(Nadaraya–Watson) |
| **n 平方** | 每个词都要和每个词比较 | 完整 Gram / 成对矩阵;数据 ×2 → 工作 ×4 |
| **KDA** | 通过滚动状态实现的线性 attention | 在线估计量(Welford / EWMA / RLS)+ delta rule |
| **残差(Residual)** | 每层之后把输入加回去 | 梯度 boosting(逐阶段修正量之和) |
| **AttnRes** | 层能复用任何更早的层,不只是紧邻那个 | 对所有先前阶段做回归,学习出来的混合 |
| **Gated MLA** | 压缩 KV cache | 低秩 / PCA 式降维,可学习的开关 |
| **SiTU** | 一个激活函数 | 单元内部的那个非线性 / 联系函数(link function) |
| **MXFP4 / MXFP8** | 用 4 / 8 位存数字 | 降低精度 —— 保留 2 位有效数字,而不是 8 位 |
| **QAT** | 训练时就意识到精度低 | 在一个知道「测量值被粗糙分箱」的前提下拟合模型 |
| **Per-Head Muon** | 训练优化器,按每个 attention head 走 | 更新权重的求解器(就像你的拟合程序) |
| **prefill / decode** | 读 prompt / 写答案 | 批处理任务 vs 实时串行请求 |
| **KV cache / cache-hit** | 复用已经见过的 token 的工作 | 对充分统计量做 memoization |
| **上下文窗口** | 一次能读多少(1M ≈ 数千页) | 估计量一次遍历能看到的样本量 |
